# ADR 0001: синхронна обробка

- **Контекст:** ПР14 вимагає walking skeleton, а на цьому етапі доступний детермінований mock.
- **Контекст:** Фонові черги, збереження стану задач та повторне опитування розширили б обсяг за межі прототипу.
- **Рішення:** `POST /api/v1/syllabi/parse` обробляє запит синхронно й повертає результат або контрольовану помилку.
- **Рішення:** Контракт використовує `request_id`, але не вводить окремі `job_id` чи стани задач.
- **Наслідки:** Інтерфейс простий, тестований і не вимагає worker-процесу.
- **Наслідки:** За повільної реальної моделі архітектуру треба переглянути окремим ADR перед запуском у production.
