# Backlog Smart Syllabus

## ПР14 — архітектура та технічний прототип (виконано)

- [x] Зафіксувати контекстну й контейнерну схеми, межу модель/код/людина та папки шарів.
- [x] Описати синхронний API, єдину форму помилки та структурований вихід дедлайнів/тем/балів.
- [x] Додати ADR щодо синхронності, сховища та провайдера/моделі.
- [x] Додати конфігурацію з перевіркою провайдера та обов'язкового ключа; секрет не входить до health/logs.
- [x] Визначити Pydantic-контракти й типізовані помилки на межах системи.
- [x] Реалізувати health, шари контролера/сервісу/orchestration/gateway/provider/storage та request_id у журналах.
- [x] Додати детермінований mock із eval-прикладами та керованими відмовами; реальний Gemini-compatible провайдер лишити заглушкою.
- [x] Додати SQLite, тонку сторінку, README та pytest-тести без реальних AI-викликів.
- [x] Позначити компонент/індекс пошуку як роботу ПР16, а не реалізовувати його в ПР14.

## Наступні етапи (не входять у ПР14)

### ПР15 — реальний провайдер і якість вилучення

- [ ] Реалізувати Gemini API за наявним контрактом, тайм-аутами та безпечним поводженням із ключем.
- [ ] Уточнити prompt, обробку неоднозначних дат/оцінок і правила повтору; зберегти людську перевірку результатів.
- [ ] Додати оцінювання якості на контрольованому наборі без запису приватного тексту до журналів.

### ПР16 — пошук

- [ ] Визначити призначення, схему й життєвий цикл окремого пошукового компонента/індексу.
- [ ] Спроєктувати індексацію та перевірки доступності окремим ADR перед реалізацією.
