# Архітектура Smart Syllabus

Позначення стану: **Є зараз (ПР14)** — реалізовано в каркасі; **Наступний етап** — лише цільова межа, не готова функція.

## Рівень 1 — контекст

```mermaid
flowchart LR
  H["Людина: студент / викладач"] -->|"HTTPS: форма, результат, помилка"| A["Smart Syllabus (Є зараз: тонкий вебінтерфейс + API)"]
  A -->|"JSON/HTTP"| C["Код застосунку (Є зараз: FastAPI)"]
  C -->|"Python: структурований запит"| M["Модель (Є зараз: deterministic mock)"]
  C -.->|"HTTPS: Gemini API (Наступний етап ПР15)" .-> G["Зовнішній LLM-провайдер"]
  C -->|"SQLite: JSON результат"| D[("SQLite (Є зараз)")]
  C -.->|"пошук/індекс, ПР16"| I[("Додатковий індекс (Наступний етап ПР16)")]
```

### Межа «модель / код / людина» з паспорта

| Сторона | Відповідальність | Стан |
|---|---|---|
| Людина | Надає текст силабуса, перевіряє дедлайни, теми й бали; ухвалює рішення щодо навчального плану. | Людина лишається відповідальною за перевірку результату. |
| Код | Приймає запит, валідовує контракти, маршрутизує провайдера, обробляє помилки, зберігає структурований результат і корелює журнали через `request_id`. | Є зараз у мінімальному вигляді. |
| Модель | Пропонує структуроване вилучення даних із наданого тексту. | Є зараз тільки підставна детермінована модель; Gemini — наступний етап ПР15. |

Застосунок не обіцяє безпомилкове вилучення й не зберігає вихідний текст силабуса. У ПР14 не виконується реальний виклик платної моделі.

`GET /api/health` перевіряє лише локальне сховище та конфігурацію: не викликає модель. Для індексу повертає `not_loaded` до ПР16.

## Папки сервера і межі залежностей

```text
app/
  main.py                 Фабрика застосунку, middleware, статична сторінка та HTTP-контролер.
  settings.py             Єдине читання й валідація конфігурації при старті.
  models.py               Контракти HTTP, провайдера, помилок та збережених сутностей.
  errors.py               Типізовані контрольовані помилки та їх HTTP-відображення.
  telemetry.py            Налаштування журналу; кореляція шарів через request_id.
  storage.py              SQLite-адаптер; не зберігає ключі або вихідний текст.
  services/               Прикладні сценарії та бізнес-потік.
  ai/                     Оркестрація AI (заготовка для ПР15).
  gateways/               Адаптер контракту провайдера та валідація його виходу.
  providers/              Абстракція й реалізації mock/Gemini-compatible.
static/                   Односторінковий інтерфейс (тонкий клієнт).
tests/                    Тести з mock і тимчасовою SQLite.
eval/                     Приклади вхідних даних та очікуваного структурованого виходу mock.
docs/                     Архітектура, API, ADR та backlog.
```

Залежності спрямовані всередину: контролер → прикладний сервіс → оркестрація → gateway → контракт провайдера; сховище викликається сервісом. Реалізація Gemini сумісного провайдера не містить мережевого виклику в ПР14. Пошуковий компонент та індекс для ПР16 не створені.

Поточний шлях основного сценарію синхронний: браузер надсилає текст, сервер повертає результат або контрольовану помилку в тому самому HTTP-запиті. До ПР14 немає черг, статусів фонового завдання чи потокової відповіді.
